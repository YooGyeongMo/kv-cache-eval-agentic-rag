# SUMMARY

이 보고서는 장문맥 멀티턴 에이전트 서비스에서 발생하는 KV cache 병목을 해결하는 두 가지 상반된 접근, ITME와 MLA를 비교한다. ITME는 하드웨어 계층을 확장해 담을 공간을 넓히는 방식이고, MLA는 소프트웨어적으로 데이터를 작게 만드는 방식이다. 두 기술 모두 병목을 완화하지만, 진입 비용과 적용 환경, 생태계 통합 방식이 정반대다. 시장성 관점에서는 생태계 확산과 표준화, 시장 규모 등 외부 신뢰성 지표가, 도메인 적용 관점에서는 실제 워크로드에서의 실효성과 성능 입증이 더 중시된다. 도메인 전환 시 두 기술이 막히는 지점도 다르다. ITME는 하드웨어 전제 조건이, MLA는 소프트웨어 구조와 메모리 요구량이 각각 한계로 작용한다. 우열을 판정하지 않고, 관점과 환경에 따라 평가가 어떻게 달라지는지에 초점을 맞췄다.

## 1. 분석 배경

장문맥 멀티턴 에이전트 서비스에서는 단일 세션의 문맥이 100K 토큰을 넘고, 대화가 이어지면서 각 턴마다 KV cache가 누적된다. 이로 인해 GPU 또는 시스템 메모리의 용량과 대역폭이 병목이 된다. KV cache는 각 토큰마다 key와 value를 저장해야 하므로, 컨텍스트 길이가 길어질수록 메모리 사용량이 기하급수적으로 증가한다. 멀티턴 대화에서는 세션이 길어질수록 캐시가 계속 쌓여, 동시 사용자 수가 많을 때 전체 메모리 압박이 심해진다.

이 병목을 해결하는 접근은 크게 두 가지로 나뉜다. 첫째는 하드웨어 계층을 확장해 담을 공간 자체를 늘리는 방식이다. ITME는 이 계열로, CXL-hybrid 메모리와 PCIe Gen5 인터페이스를 활용해 대용량 데이터를 원격 계층에 오프로드한다. 둘째는 소프트웨어적으로 데이터를 작게 만들어 캐시 자체의 크기를 줄이는 방식이다. MLA는 어텐션 구조를 바꿔 KV cache를 처음부터 작게 만든다. 이 두 접근은 진입 비용, 적용 환경, 기존 시스템과의 호환성에서 상반된 특성을 보인다. 한쪽은 하드웨어를 그대로 두고 모델 구조를 바꿔야 하고, 다른 쪽은 모델을 그대로 두고 새 하드웨어를 들여야 한다.

이처럼 같은 병목을 두고 무엇을 바꿀 것인지가 정반대이기 때문에, 우열을 판정하지 않고도 관점에 따라 평가가 갈리는 모습을 비교할 수 있다.

## 2. 기술 선정

이 보고서의 기술 선정은 에이전트가 아니라 사람이 Doc Pool에서 진영별로 하나씩 직접 골랐다. 선정 기준은 진입 비용의 대칭성이다. 한쪽은 하드웨어를 그대로 두는 대신 모델 쪽을 바꿔야 하고, 다른 쪽은 모델을 그대로 두는 대신 새 메모리 하드웨어를 들여야 한다. 같은 병목을 두고 무엇을 바꿀 것인지가 정반대라서, 관점에 따라 평가가 갈리는 모습을 드러낼 수 있다.

MLA(소프트웨어, 데이터를 작게 만들기)는 소프트웨어 진영에서 가장 근본적인 형태를 고른 것이다. 사후 압축은 이미 만들어진 KV cache를 줄이지만, MLA는 어텐션 구조 자체를 바꿔 처음부터 작게 나오게 한다. 압축률 93.3퍼센트[MLA p.1]로 진영 안에서 가장 큰 수치를 보고했고, 실제 상용 모델에 배포되어 시장 근거를 모을 수 있다. 진입 비용을 볼 때는 기법 자체와 후속 연구를 구별해야 한다. MLA는 그 구조로 사전학습한 모델을 전제하므로 기존 모델에 그대로 얹을 수 없고, 기존 모델을 MLA로 바꾸려면 TransMLA 같은 별도 전환 연구를 거쳐야 한다.

ITME(하드웨어, 담을 공간을 넓히기)는 하드웨어 진영에서 분류가 흔들리지 않는 것을 고른 것이다. 같은 진영의 InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 진영 구분이 흐려진다. ITME는 CXL 메모리라는 새 하드웨어 계층을 전제하므로 진입 비용의 성격이 MLA와 정확히 대비되고, 멀티턴 워크로드를 정면으로 측정해 주 도메인과도 맞는다.

같은 Doc Pool에서 뺀 후보와 그 이유는 다음과 같다. TurboQuant와 KIVI는 사후 압축 계열로, MLA와 같은 진영이라 한 진영에서 둘을 고를 수 없다. InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 하드웨어 진영 대표로 두면 비교 축이 흐려진다. PIM/CXL은 수치는 가장 크지만 데이터센터급 PIM의 상용 채택 근거가 확인되지 않아 시장성 관점에서 수집할 근거가 한쪽으로 빈다.

## 3. 기술 개요

### ITME

ITME는 KV cache 메모리 병목을 해결하기 위해 LLM 데이터 타입을 예측 가능성과 성능 중요도에 따라 계층화한다. 활성화와 작업 중인 KV cache는 고속 GPU 또는 호스트 메모리 계층에 두고, 대용량이면서 예측 가능한 모델 가중치와 장문맥 KV cache는 CXL-hybrid 메모리를 사용하는 원격 확장 계층에 오프로드한다. 이 과정에서 하드웨어와 소프트웨어가 협조하는 프리페칭을 사용해 저장장치와 네트워크 지연을 가린다. NVMe SSD에서 DRAM 캐시로의 하드웨어 프리페칭, PCIe Gen5 인터페이스를 통한 고속 KV cache 교체가 핵심이다. 이런 다계층 메모리 관리는 TB급 LLM 워크로드에서 대용량 KV cache를 효율적으로 처리할 수 있게 한다[ITME p.2][ITME p.11].

보고된 수치는 CPU-offload 베이스라인 대비 35.7퍼센트 throughput 개선이다. 이는 35턴 벤치마크, 256개 동시 대화(ShareGPT 데이터셋), recomputation 베이스라인에 대해 정규화한 결과다. CPU-offload 베이스라인(T2 계층)은 캐싱에 128 GB 호스트 메모리를 할당한다. ITME는 CXL-hybrid 메모리(T3.5 계층)를 사용하며, 호스트 메모리(T2)는 스테이징 버퍼로 일부만 쓴다[ITME p.9][ITME p.11].

성립 조건은 다음과 같다. 고속 GPU 또는 호스트 메모리 계층과 CXL-hybrid 메모리를 갖춘 원격 확장 계층이 필요하다. PCIe Gen5 인터페이스, 하드웨어/소프트웨어 협조 프리페칭, NVMe SSD 연동이 전제된다. 워크로드는 대용량, 예측 가능한 모델 가중치와 장문맥 KV cache를 가진 TB급 LLM 추론이어야 한다[ITME p.11].

저자가 밝힌 한계는 I/O 경합이 심할 때 예측 불가능한 I/O stall로 인한 성능 변동이 있다는 점이다. 이는 read-priority 스케줄링으로 일부 완화된다. 이외의 명시적 한계는 없다[ITME p.11].

### MLA

MLA(Multi-head Latent Attention)는 추론 시 발생하는 KV cache 병목을 해결하기 위해 key와 value를 저차원 잠재 벡터로 함께 압축한다. 기존 Multi-Head Attention(MHA) 대비 훨씬 작은 KV cache로 동등 이상의 성능을 낸다. MLA는 어텐션 구조 자체를 바꿔, KV cache가 처음부터 작게 생성되도록 한다[MLA p.1].

보고 수치는 MLA가 93.3퍼센트의 KV cache 압축률을 달성했다는 것이다[MLA p.1]. 이 수치는 MLA 구조를 적용한 DeepSeek-V2 모델에서 보고된 값이다. MLA 자체의 성능 수치나 비교 기준선에 대한 추가 근거는 없다.

성립 조건은 Transformer 프레임워크 내에서 multi-head attention 계산 시 key-value를 저차원으로 합쳐 압축할 수 있어야 한다는 점이다. 표준 Transformer 구조와 multi-head attention을 전제로 한다[MLA p.1].

저자가 밝힌 한계는 근거가 없다.

## 5. 시사점

두 기술의 진입 비용은 정반대 방향이다. ITME는 기존 모델을 그대로 두고 하드웨어 계층을 확장해야 하며, MLA는 하드웨어를 그대로 두고 모델 구조를 바꿔야 한다. 이 차이는 도입 결정에서 관점에 따라 평가가 달라지는 핵심 요인이다.

이 표가 말하는 바는 다음과 같다. 주 도메인인 장문맥 멀티턴 에이전트 서비스에서는 두 기술 모두 적용 가능하다. 그러나 온디바이스 추론 도메인에서는 MLA는 메모리 요구량과 하드웨어 전제 조건 때문에, ITME는 CXL-hybrid 메모리 등 하드웨어 인프라 부재로 각각 막힌다. 클라우드 대규모 동시 서빙에서는 MLA는 별다른 제약 없이 적용 가능하지만, ITME는 CXL 인프라 도입과 운영 복잡도, 상용 하드웨어 부족이 한계로 작용한다. 즉, 동일 기술도 적용 환경에 따라 막히는 지점이 다르며, 관점과 도메인에 따라 평가가 달라진다.

## 6. 한계점

이 평가는 1인 과제 범위로 한정했다. 기술 성숙도(TRL) 관점과 이해관계자 관점은 범위에서 뺐다. 빠뜨린 것이 아니라 뺀 것이다. 두 기술의 공개 시점이 2년 차이 나므로, 채택 현황을 나란히 놓으면 늦게 나온 쪽이 불리하게 읽힌다. 이 시간 차이를 감안하고 읽어야 한다.

시장 근거는 공개 자료만 썼다. 반도체 업계는 수율과 원가를 공개하지 않으므로 실제 채택 규모는 공개 정보로 확인할 수 없다. 웹 근거에 출처 등급을 붙였다. 일차는 논문, 코드 저장소, 벤더 공식 문서이고, 시장조사는 상업 조사기관 요약이다. 시장 규모 수치는 대부분 시장조사 등급이며, 원본 보고서를 열어 대조하지 못했다. 같은 범주를 두고도 조사기관마다 수치가 크게 다른 경우가 있으므로 단일 수치를 그대로 믿으면 안 된다.

수집된 웹 근거의 등급 분포는 ITME가 일차 14건, 이차 42건, 시장조사 0건이고, MLA는 일차 7건, 이차 49건, 시장조사 0건이다. 확증편향 감사에서 한쪽으로 기운 항목은 나오지 않았다. 취한 조치는 다음과 같다. 두 기술에 같은 질문 템플릿을 썼고, 관점마다 유리한 근거와 불리한 근거를 각각 따로 검색했다. 기술 제시 순서를 바꿔 두 번 실행하고 결론이 달라지는지 확인했다. 모든 평가 문장에 근거 원장의 id를 달았고, 수치가 근거 원문에 있는지 코드로 대조했다. 한쪽을 높이거나 권하는 표현을 금지어 목록으로 두고 검사했다.

웹 근거가 개별 기술이 아니라 범주 수준이었던 항목이 있다. 예를 들어 시장 규모 수치는 CXL 메모리 확장이나 LLM 전체 시장을 가리키며, ITME나 MLA 기술 자체를 직접 지칭하지 않는다. 이 점을 해석에 반영해야 한다.
