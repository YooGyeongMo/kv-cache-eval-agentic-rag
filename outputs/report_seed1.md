# SUMMARY

이 보고서는 장문맥 멀티턴 에이전트 서비스 도메인에서 Key-Value(KV) cache 병목을 해결하는 두 가지 대표적 접근인 ITME(CXL-hybrid 메모리 기반 하드웨어 확장)와 MLA(Multi-head Latent Attention, 소프트웨어 구조 변경)를 대조한다. 두 기술은 진입 비용의 방향이 정반대이며, ITME는 하드웨어를 바꾸고 소프트웨어를 그대로 두는 쪽, MLA는 소프트웨어 구조를 바꾸고 하드웨어를 그대로 두는 쪽을 대표한다. 시장성 관점에서는 생태계 채택 현황과 도입 비용 정보의 부재가, 도메인 적용 관점에서는 실제 운영 복잡도와 하드웨어 가용성, 정확도 검증의 부재가 각각 평가에 영향을 준다. 도메인을 온디바이스 추론이나 클라우드 대규모 동시 서빙으로 바꿀 때 두 기술의 적용 가능성과 한계가 다르게 드러난다. 어느 쪽이 더 낫다고 단정하지 않고, 관점과 도메인에 따라 평가가 어떻게 달라지는지에 초점을 맞춘다.

## 1. 분석 배경

장문맥 멀티턴 에이전트 서비스에서는 단일 세션의 문맥이 수십만 토큰에 이르고, 대화가 이어질수록 Key-Value(KV) cache가 턴마다 누적된다. 이때 KV cache의 크기와 접근 속도가 추론 효율의 병목이 된다. 기존 GPU 메모리만으로는 TB 단위의 KV cache와 모델 가중치를 모두 담기 어렵고, CPU 오프로딩이나 SSD 기반 확장은 대역폭과 지연에서 한계가 있다. 이 병목을 해결하려는 접근은 크게 두 갈래로 나뉜다.

첫째, 하드웨어 계층을 확장해 담을 공간을 넓히는 방식이다. 대표적으로 ITME는 CXL-hybrid 메모리와 PCIe Gen5 인터페이스를 도입해, 대용량 모델 가중치와 장문맥 KV cache를 원격 확장 계층에 오프로드한다. 하드웨어의 대역폭과 계층 구조를 활용해 병목을 완화한다.

둘째, 소프트웨어 구조를 바꿔 데이터를 처음부터 작게 만드는 방식이다. MLA는 어텐션 구조 자체를 변경해, KV cache를 저랭크 잠재 벡터로 압축한다. 기존 Multi-Head Attention(MHA) 대비 KV cache 요구량을 크게 줄여, 같은 하드웨어에서 더 많은 문맥과 세션을 처리할 수 있게 한다.

이 두 접근은 진입 비용의 방향이 정반대다. ITME는 하드웨어를 바꿔야 하지만 기존 모델과 소프트웨어를 그대로 쓸 수 있다. MLA는 하드웨어를 그대로 두지만 모델 구조를 바꿔야 하며, 기존 모델을 그대로 쓸 수 없고, 재학습이나 구조 전환이 필요하다. 어느 쪽이 더 낫다고 단정할 수 없으며, 관점과 도메인에 따라 평가가 갈린다.

## 2. 기술 선정

이 보고서에서 다루는 두 기술은 사람이 Doc Pool에서 진영별로 하나씩 직접 골랐다. 선정 기준은 진입 비용의 대칭성이다. 한쪽은 하드웨어를 그대로 두는 대신 모델 쪽을 바꿔야 하고, 다른 쪽은 모델을 그대로 두는 대신 새 메모리 하드웨어를 들여야 한다. 같은 병목을 두고 무엇을 바꿀 것인지가 정반대라서, 우열을 판정하지 않고도 관점에 따라 평가가 갈리는 모습을 드러낼 수 있다.

MLA(소프트웨어, 데이터를 작게 만들기)는 소프트웨어 진영에서 가장 근본적인 형태를 고른다. 사후 압축은 이미 만들어진 KV cache를 줄이지만 MLA는 어텐션 구조 자체를 바꿔 처음부터 작게 나오게 한다. 압축률 93.3퍼센트[MLA p.1]로 진영 안에서 가장 큰 수치를 보고했고, 실제 상용 모델에 배포되어 시장 근거를 모을 수 있다. 진입 비용을 볼 때는 기법 자체와 후속 연구를 구별해야 한다. MLA는 그 구조로 사전학습한 모델을 전제하므로 기존 모델에 그대로 얹을 수 없고, 기존 모델을 MLA로 바꾸려면 TransMLA 같은 별도 전환 연구를 거쳐야 한다.

ITME(하드웨어, 담을 공간을 넓히기)는 하드웨어 진영에서 분류가 흔들리지 않는 것을 고른다. 같은 진영의 InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 진영 구분이 흐려진다. ITME는 CXL 메모리라는 새 하드웨어 계층을 전제하므로 진입 비용의 성격이 MLA와 정확히 대비되고, 멀티턴 워크로드를 정면으로 측정해 주 도메인과도 맞는다.

같은 Doc Pool에서 뺀 후보와 그 이유는 다음과 같다. TurboQuant와 KIVI는 사후 압축 계열로, MLA와 같은 진영이라 한 진영에서 둘을 고를 수 없다. InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 하드웨어 진영 대표로 두면 비교 축이 흐려진다. PIM/CXL은 수치는 가장 크지만 데이터센터급 PIM의 상용 채택 근거가 확인되지 않아 시장성 관점에서 수집할 근거가 한쪽으로 빈다.

## 3. 기술 개요

### ITME

ITME는 CXL-hybrid 메모리와 PCIe Gen5 인터페이스를 활용해, 대용량 LLM 추론에서 메모리 용량을 확장하는 하드웨어 기반 기법이다. 다계층 DMA 기반 프리페칭 메커니즘으로 데이터 전송 파이프라인을 GPU 연산과 겹쳐 지연을 숨기고, 모델 가중치와 장문맥 KV cache처럼 크고 예측 가능한 데이터를 원격 확장 계층에 오프로드한다. NVMe SSD에서 내부 DRAM 캐시로 하드웨어 프리페칭을 수행하고, 기존 소프트웨어 캐시 관리 정책과 연동한다.

보고된 수치는 다음과 같다. CPU-offload 베이스라인(128 GB host memory) 대비 extended turns에서 35.7퍼센트 throughput 개선이 있다[ITME p.10]. 성능 평가는 256개 동시 대화(ShareGPT 데이터셋)와 35턴 벤치마크로 이루어졌다[ITME p.9]. CPU-offload 베이스라인의 캐싱 용량은 128 GB였다[ITME p.9].

ITME의 성립 조건은 PCIe Gen5 기반 CXL-hybrid 메모리와 NVMe SSD, GPU 및 호스트 메모리 계층이 모두 갖춰진 환경이다. TB 단위 메모리 풋프린트가 필요한 대규모 LLM 워크로드, 특히 모델 가중치와 장문맥 KV cache를 대상으로 한다. vLLM 프레임워크 내에 구현되어 있다.

저자가 밝힌 한계로는, 강한 경쟁 상황에서 예측 불가한 I/O stall로 인한 성능 변동이 있으나 read-priority 스케줄링으로 완화된다고 한다. PCIe Gen4 기반 CXL-hybrid 메모리 프로토타입은 대역폭이 제한적이지만, ITME는 PCIe Gen5를 채택해 이를 해결했다고 한다. 이외에 ITME 자체의 명시적 한계는 언급되지 않았다.

### MLA

MLA(Multi-head Latent Attention)는 어텐션 구조를 변경해, Key와 Value를 저랭크 잠재 벡터로 공동 압축한다. 이를 통해 기존 Multi-Head Attention(MHA) 대비 KV cache 요구량을 크게 줄이고, 인퍼런스 효율을 높인다.

보고된 수치는 다음과 같다. DeepSeek 67B(MHA 대비) 기준 KV cache 93.3퍼센트 감소, 학습 비용 42.5퍼센트 절감, 최대 생성 처리량 5.76배 증가, 21B 활성 파라미터로 오픈소스 모델 상위권 성능 달성 등이 있다.

MLA의 성립 조건은 Transformer 기반 모델 구조와 어텐션 모듈이 필요하며, 128K context length(DeepSeek-V2 기준)와 저랭크 key-value joint compression이 가능해야 한다.

저자가 밝힌 한계는 근거에 없다.

| 채택_깊이    | 구현이 기본값인지 선택 옵션인지, 안정성 등급이나 기본값 여부에 관한 정보는 없다[ITME p.11]. | MLA가 기본값인지 선택 옵션인지, 실험 기능인지에 대한 정보는 없다[MLA p.4][MLA p.6]. |

유리한 점으로 ITME는 기존 생태계와의 호환성을 고려해 설계되었고, PCIe Gen5로 고대역폭을 제공한다[ITME p.11]. MLA는 KV cache를 크게 줄여 인퍼런스 효율을 높이는 구조적 혁신을 보인다[MLA p.6]. 불리한 점으로 두 기술 모두 채택 현황, 도입 비용, 생태계 지지, 시장 규모에 관한 구체적 정보가 없다.

| 증거_성숙도  | Llama-3.1 8B 및 70B, ShareGPT, Mooncake 데이터셋으로 다중 턴 대화 워크로드 평가. 상용 CXL 하드웨어 부족으로 일부 연구는 시뮬레이션/에뮬레이션 의존[ITME p.9][ITME p.11]. | 보고된 수치는 저자 자체 보고. 도메인 내 실제 측정 수치, 제3자 검증 여부 정보 없음[MLA p.6][MLA p.4]. |

유리한 점으로 ITME는 TB 규모 LLM 워크로드의 메모리 용량 문제를 해결하고, 기존 인프라와 연계가 가능하다[ITME p.2][ITME p.11]. MLA는 KV cache를 크게 줄여 장문맥 멀티턴 서비스의 병목과 일치한다[MLA p.6][MLA p.4]. 불리한 점으로 ITME는 하드웨어 가용성, 운영 복잡도, 정확도 평가의 부재가 있고, MLA는 정확도 손실 수치, 운영 비용 변화, 제3자 검증 정보가 없다.

## 5. 시사점

두 기술은 진입 비용의 방향이 정반대다. ITME는 하드웨어를 바꿔야 하지만 기존 소프트웨어와 모델을 그대로 쓸 수 있다. MLA는 하드웨어를 그대로 두지만 모델 구조를 바꿔야 하며, 기존 모델을 그대로 쓸 수 없고 재학습이나 구조 전환이 필요하다. 이 대칭성 때문에, 관점에 따라 평가가 달라진다.

시장성 관점에서는 ITME가 기존 생태계와의 호환성을 고려해 설계되었다고 밝히지만, 실제로 주요 추론 스택이나 상용 제품의 어느 계층에 구현되었는지, 기본값인지 선택 옵션인지에 관한 정보가 없다[ITME p.11]. 도입 시 기존 가중치 재학습이나 하드웨어 교체 필요성에 대한 정보도 없어, 채택 가능성의 불확실성이 부각된다[ITME p.1][ITME p.11]. 도메인 적용 관점에서는 CXL 하이브리드 메모리와 NVMe SSD 간 데이터 이동 및 프리페칭 관리가 추가되어 운영 복잡도가 증가할 수 있고, 상용 CXL 하드웨어의 제한적 가용성이 현실적 제약으로 작용한다[ITME p.11][ITME p.2].

MLA는 시장성 관점에서 주요 추론 스택이나 상용 제품의 어느 계층에 구현되었는지, 기본값인지 선택 옵션인지, 도입 비용과 생태계 지지에 관한 정보가 전혀 없다[MLA p.4][MLA p.6][MLA p.7]. 도메인 적용 관점에서는 운영 복잡도 변화나 신규 인프라 요구사항에 대한 정보가 없어, 실제 운영 환경에서의 비용 변화와 인프라 요구사항의 불명확성이 문제로 지적된다[MLA p.6]. 두 관점 모두 정보 부재를 문제 삼지만, 시장성은 '시장 내 확산'에, 도메인은 '현장 적용'에 초점을 둔다.

정확도 및 성능 검증에서도 관점이 갈린다. MLA는 MHA 대비 성능이 더 높다고 보고되지만, 정확도 손실 수치나 측정 조건이 구체적으로 제시되지 않아 도메인의 정확도 허용치 내에 있는지 판단하기 어렵다[MLA p.6]. 시장성 관점에서는 시장 규모와 성장 전망의 부재가 불리하게 읽히고, 도메인 관점에서는 정확도 및 실제 환경 검증의 부재가 불리하게 읽힌다.

도메인을 바꿀 때 두 기술의 적용 가능성과 한계도 다르게 드러난다. ITME는 온디바이스 추론(스마트폰, 엣지 등)에서는 PCIe Gen5, CXL, NVMe SSD 등 고성능 서버급 하드웨어가 일반적으로 제공되지 않으므로 적용이 어렵다. 클라우드 대규모 동시 서빙에서는 다계층 메모리 구조와 프리페칭이 동시성 확장에 유리할 수 있으나, 실제 비용 절감 효과나 동시 세션 수에 대한 수치는 없다. MLA는 온디바이스 추론에서 KV cache 감소가 유리하게 작용할 수 있으나, 실제 적용 사례나 전력 효율 수치는 없다. 클라우드 대규모 동시 서빙에서는 세션당 메모리 사용량 감소가 동시 처리량 증가에 기여할 수 있으나, 실제 수치는 없다.

이처럼 두 기술은 같은 병목을 두고 정반대 방향의 진입 비용을 요구하며, 도메인 전환 시 막히는 지점도 다르다. ITME는 하드웨어 전제에서, MLA는 소프트웨어 구조 전제에서 각각 한계가 드러난다.

## 6. 한계점

이 평가는 1인 과제 범위로 한정했다. 기술 성숙도(TRL) 관점과 이해관계자 관점은 범위에서 뺐다. 빠뜨린 것이 아니라 뺀 것이다. 두 기술의 공개 시점이 2년 차이 나므로, 채택 현황을 나란히 놓으면 늦게 나온 쪽이 불리하게 읽힌다. 이 시간 차이를 감안하고 읽어야 한다.

시장 근거는 공개 자료만 썼다. 반도체 업계는 수율과 원가를 공개하지 않으므로 실제 채택 규모는 공개 정보로 확인할 수 없다. 웹 근거에 출처 등급을 붙였으며, ITME와 MLA 모두 개별 기술이 아니라 범주 수준의 시장조사만 있었다. 시장 규모 수치는 대부분 시장조사 등급이며, 원본 보고서를 열어 대조하지 못했다. 같은 범주를 두고도 조사기관마다 수치가 크게 다르므로 단일 수치를 그대로 믿으면 안 된다.

확증편향을 막기 위해 두 기술에 같은 질문 템플릿을 쓰고, 찬반 근거를 각각 따로 검색했다. 기술 제시 순서를 바꿔 두 번 실행하고, 결론이 달라지는지 확인했다. 모든 평가 문장에 근거 원장의 id를 달았고, 수치는 근거 원문에 있는지 코드로 대조했다. 우열을 판정하는 표현은 금지어 목록으로 검사했다. 그러나 공개 정보만으로는 실제 운영 환경에서의 성능, 비용, 채택 현황, 생태계 지지, 정확도 손실 등 핵심 정보를 모두 확인할 수 없다. 웹 근거가 개별 기술이 아니라 범주 수준이었던 항목이 있으므로, 해당 수치는 기술 고유의 시장성 근거로 쓸 수 없다.
