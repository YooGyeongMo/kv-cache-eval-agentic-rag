# SUMMARY

이 보고서는 장문맥 멀티턴 에이전트 서비스 도메인에서 Key-Value(KV) cache 병목을 해결하는 두 가지 대표적 접근, DeepSeek-V2 Multi-head Latent Attention(MLA, 소프트웨어)와 ITME: Inference Tiered Memory Expansion with Disaggregated CXL-Hybrid Memories(ITME, 하드웨어)를 대조한다. MLA는 어텐션 구조 자체를 바꿔 KV cache를 처음부터 작게 만들고, ITME는 CXL 기반 메모리 확장으로 담을 공간을 넓힌다. 두 기술은 진입 비용의 방향이 정반대이며, 시장성 관점에서는 생태계 채택과 도입 비용, 도메인 적용 관점에서는 실제 운영 복잡도와 하드웨어 전제 조건에서 평가가 갈린다. 도메인을 바꾸면 두 기술의 제약도 달라진다. 모든 평가는 공개 근거에 한정했으며, 우열 판정 없이 관점별 대조에 집중했다.

## 1. 분석 배경

장문맥 멀티턴 에이전트 서비스는 단일 세션에서 100K 토큰이 넘는 문맥을 유지하며, 대화가 이어질수록 Key-Value(KV) cache가 턴마다 누적된다. 이때 KV cache의 크기가 메모리 용량과 대역폭의 병목으로 작용한다. 기존 Transformer 기반 모델은 각 토큰마다 KV 쌍을 저장해 문맥이 길어질수록 메모리 요구량이 선형적으로 증가한다. 멀티턴 환경에서는 세션이 늘어날수록 전체 시스템의 메모리와 대역폭 부담이 급격히 커진다.

이 병목을 해결하는 접근은 크게 두 갈래로 나뉜다. 첫째는 소프트웨어적으로 KV cache 자체를 작게 만드는 것이다. 어텐션 구조를 바꿔 저장해야 할 데이터를 줄이거나, 사후 압축으로 이미 생성된 KV cache를 줄이는 방식이 있다. 둘째는 하드웨어적으로 담을 공간을 넓히는 것이다. 메모리 계층을 확장하거나, 고속 인터페이스를 통해 원격 메모리까지 활용하는 방식이 대표적이다.

이 두 접근은 진입 비용의 방향이 정반대다. 소프트웨어 방식은 모델 구조나 학습 과정을 바꿔야 하므로 기존 하드웨어를 그대로 두는 대신 모델 쪽을 바꾼다. 하드웨어 방식은 모델을 그대로 두는 대신 새 메모리 하드웨어를 들여야 한다. 같은 병목을 두고 무엇을 바꿀 것인지가 완전히 다르다. 이 때문에 우열을 판정하지 않고도 관점에 따라 평가가 갈리는 모습을 드러낼 수 있다.

## 2. 기술 선정

기술 선정은 에이전트가 아니라 사람이 Doc Pool에서 진영별로 하나씩 직접 골랐다. 선정 기준은 진입 비용의 대칭성이다. 한쪽은 하드웨어를 그대로 두는 대신 모델 쪽을 바꿔야 하고, 다른 쪽은 모델을 그대로 두는 대신 새 메모리 하드웨어를 들여야 한다. 같은 병목을 두고 무엇을 바꿀 것인지가 정반대라서, 우열을 판정하지 않고도 관점에 따라 평가가 갈리는 모습을 드러낼 수 있다.

MLA(소프트웨어, 데이터를 작게 만들기)는 소프트웨어 진영에서 가장 근본적인 형태를 고른다. 사후 압축은 이미 만들어진 KV cache를 줄이지만 MLA는 어텐션 구조 자체를 바꿔 처음부터 작게 나오게 한다. 압축률 93.3퍼센트[MLA p.1]로 진영 안에서 가장 큰 수치를 보고했고, 실제 상용 모델에 배포되어 시장 근거를 모을 수 있다. 진입 비용을 볼 때는 기법 자체와 후속 연구를 구별해야 한다. MLA는 그 구조로 사전학습한 모델을 전제하므로 기존 모델에 그대로 얹을 수 없고, 기존 모델을 MLA로 바꾸려면 TransMLA 같은 별도 전환 연구를 거쳐야 한다.

ITME(하드웨어, 담을 공간을 넓히기)는 하드웨어 진영에서 분류가 흔들리지 않는 것을 고른다. 같은 진영의 InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 진영 구분이 흐려진다. ITME는 CXL 메모리라는 새 하드웨어 계층을 전제하므로 진입 비용의 성격이 MLA와 정확히 대비되고, 멀티턴 워크로드를 정면으로 측정해 주 도메인과도 맞는다.

같은 Doc Pool에서 뺀 후보와 그 이유는 다음과 같다. TurboQuant와 KIVI는 사후 압축 계열로, MLA와 같은 진영이라 한 진영에서 둘을 고를 수 없다. InfiniGen은 기존 하드웨어 위에서 도는 소프트웨어 기법이라 하드웨어 진영 대표로 두면 비교 축이 흐려진다. PIM/CXL은 수치는 가장 크지만 데이터센터급 PIM의 상용 채택 근거가 확인되지 않아 시장성 관점에서 수집할 근거가 한쪽으로 빈다.

## 3. 기술 개요

### MLA (DeepSeek-V2 Multi-head Latent Attention)

MLA는 Multi-head Latent Attention 구조를 통해 추론 시 Key-Value(KV) cache 병목을 완화한다. 기존 Multi-Head Attention(MHA) 대비, 키와 값을 저랭크(latent) 벡터로 결합 압축하여 KV cache 요구량을 크게 줄인다. MLA는 DeepSeek 67B 모델 기준으로 93.3퍼센트의 KV cache 감소, 42.5퍼센트의 학습 비용 절감, 최대 5.76배의 생성 처리량 증가를 보고했다[MLA p.1]. 이 기법은 최대 128K 토큰의 장문맥을 지원하며, Transformer 기반 모델에서 multi-head attention과 저랭크 key-value 결합 압축을 지원해야 한다. 저자가 밝힌 한계는 근거에 없다.

### ITME (Inference Tiered Memory Expansion with Disaggregated CXL-Hybrid Memories)

ITME는 CXL-hybrid 메모리와 다계층 DMA 기반 프리페칭을 활용해 LLM 추론의 메모리 용량을 확장한다. 대용량 모델 가중치와 장문맥 KV cache를 원격 확장 계층에 오프로드하고, 하드웨어/소프트웨어 프리페칭으로 접근 지연을 숨긴다. ITME는 256개 동시 대화(ShareGPT 데이터셋, 35턴) 기준 CPU-offload 대비 35.7퍼센트의 처리량 개선을 보고했다[ITME p.11][ITME p.2]. CPU-offload 기준 호스트 메모리 용량은 128GB이며, ITME는 PCIe Gen5 기반 CXL-hybrid 메모리(T3.5)와 호스트 메모리 스테이징(T2)을 계층화한다. 성립 조건은 GPU, 호스트 메모리, CXL-hybrid 메모리 계층이 필요하며, 대용량 데이터의 예측 가능성이 높아야 한다. 저자가 밝힌 한계는 I/O 경합 시 성능 변동이 있으며, CPU-offload 한계를 넘어서면 ITME 없이는 캐싱이 붕괴된다는 점이다.

## 4. 관점별 평가

### 4.1 시장성 관점

| 기준        | MLA | ITME |
|-------------|-----|------|
| 채택_폭     | DeepSeek-V2의 MLA가 Transformer 프레임워크 내 attention 모듈에 적용된 것으로 보이나, 주요 추론 스택(vLLM, SGLang, TensorRT-LLM, llama.cpp, HuggingFace transformers)이나 상용 제품의 커널, 서빙 엔진, SDK, 하드웨어 제품 계층에 구현되었다는 직접적 언급은 없다[MLA p.4][MLA p.6][MLA p.7]. | ITME는 기존 소프트웨어 스택을 대체하지 않고 보완하는 메모리 확장 아키텍처로 설계되었으나, 주요 추론 스택이나 상용 제품의 어느 계층에 구현되었는지에 대한 직접적 언급은 없다[ITME p.11]. |
| 채택_깊이   | MLA가 기본값인지 선택 옵션인지 실험 기능인지에 대한 안정성 등급이나 기본값 여부에 관한 언급은 없다[MLA p.4][MLA p.6]. | ITME 구현이 기본값인지, 선택 옵션인지, 실험 기능인지에 대한 정보는 없다[ITME p.11]. |
| 진입_비용   | MLA는 기존 MHA 대비 KV 캐시를 크게 줄이면서 성능을 유지하거나 향상시키는 저랭크 키-값 결합 압축 기법이나, 도입 시 기존 가중치 유지, 재학습 필요성, 하드웨어 변경 요구에 대한 정보는 없다[MLA p.4][MLA p.6]. | ITME는 CXL-hybrid 메모리를 활용해 TB 규모 메모리 확장을 제공하며, PCIe Gen5 인터페이스를 채택한다. 도입 시 기존 가중치 재학습 필요성이나 하드웨어 교체 요구에 대한 구체적 언급은 없다[ITME p.1][ITME p.11]. |
| 생태계_지지 | MLA를 베이스라인으로 삼은 후속 연구, 표준 규격, 컨소시엄, 독립 제3자 재현 결과 공개에 관한 정보는 없다[MLA p.4][MLA p.6]. | ITME를 베이스라인으로 삼은 후속 연구, 표준 규격, 컨소시엄, 독립 제3자 재현 결과 공개 여부는 언급되지 않는다[ITME p.11]. |
| 시장_수치   | MLA 또는 DeepSeek-V2 관련 시장 규모, 성장 전망 수치, 조사기관, 발표 시점에 관한 정보는 없다. | ITME 기술 자체에 대한 시장 규모나 성장 전망 수치는 없으며, CXL 메모리 확장 및 풀링 범주에 대한 시장 조사는 있으나 이는 상위 범주에 대한 관찰임을 명시한다. ITME 기술의 시장 수치 근거는 없다. |

유리한 점: MLA는 기존 MHA 대비 성능이 더 좋으면서 KV 캐시를 크게 줄여 추론 효율을 높이는 혁신적 주의 메커니즘으로 설계되었다[MLA p.4][MLA p.6]. ITME는 기존 소프트웨어 스택과 호환되며 이를 대체하지 않고 보완하는 아키텍처로 설계되어, 기존 환경과의 통합 가능성을 시사한다[ITME p.11]. PCIe Gen5 인터페이스를 채택해 대규모 LLM 추론에 적합한 성능을 목표로 한다[ITME p.11].

불리한 점: MLA와 ITME 모두 주요 추론 스택이나 상용 제품의 어느 계층에 구현되었는지, 기본값인지, 도입 비용과 생태계 지지에 관한 구체적 정보가 없다[MLA p.4][MLA p.6][MLA p.7][ITME p.11]. ITME는 도입 시 필요한 하드웨어 교체, 재학습 여부 등 진입 비용 관련 구체적 정보가 없어 시장 진입 장벽 평가가 어렵다[ITME p.1][ITME p.11]. 두 기술 모두 시장 규모나 성장 전망 수치가 없다.

근거 없음: 두 기술 모두 채택_폭, 채택_깊이, 진입_비용, 생태계_지지, 시장_수치에 관한 구체적 근거가 없다.

### 4.2 도메인 적용 관점

| 기준        | MLA | ITME |
|-------------|-----|------|
| 병목_일치   | 이 도메인의 병목인 KV cache의 크기와 관련된 메모리 용량 및 대역폭 문제를 직접 겨냥한다. MLA는 KV cache를 크게 줄여 이 병목을 해결한다는 점에서 일치한다. 지연, 전력에 대한 직접 언급은 없다[MLA p.6][MLA p.7]. | 메모리 용량, 대역폭, 지연이 병목인 환경에서 대용량 모델 가중치와 장문맥 KV 캐시를 원격 확장 계층에 오프로드하고, PCIe Gen5로 대역폭 병목을 줄인다[ITME p.2][ITME p.11]. |
| 자원_전제   | 하드웨어 전제 조건에 대한 구체적 언급은 없으나, KV cache 감소를 통해 기존 Transformer 하드웨어 환경에서 적용 가능할 것으로 보인다. 명확한 전제 조건은 제시되지 않았다[MLA p.6][MLA p.7]. | PCIe Gen5 기반 CXL-하이브리드 메모리와 NVMe SSD, GPU 및 호스트 메모리 계층이 필요하다. 상용 CXL 하드웨어가 제한적이며, PCIe Gen4 대비 Gen5가 필수적이다[ITME p.11]. |
| 정확도_허용치 | MLA는 MHA 대비 성능이 더 좋다고 보고되었으며, MHA, GQA, MQA와의 성능 비교 및 ablation 결과가 부록에 있으나, 구체적 정확도 손실 수치나 측정 조건(모델 크기, 문맥 길이, 과제 종류)은 본문에 명시되어 있지 않다[MLA p.6][MLA p.4]. | 근거 없음. |
| 운영_비용   | 운영 복잡도 변화, 별도 패치 관리, 신규 인프라, 전송 계층 추가 등에 관한 언급은 전혀 없으며, 도입 후 운영 비용 변화에 대한 정보는 없다[MLA p.4][MLA p.6]. | 기존 소프트웨어 오프로드 스택과 호환되며, 다계층 캐시 관리 정책과 신규 CXL-하이브리드 메모리 인프라, PCIe Gen5 네트워크 계층 도입이 요구된다[ITME p.11][ITME p.2]. |
| 증거_성숙도 | MLA의 성능 및 KV cache 감소 효과는 저자 자체 보고이며, 도메인 특화된 실제 측정 수치인지, 제3자 검증인지 구분할 수 있는 근거는 없다[MLA p.6][MLA p.4]. | Llama-3.1 8B 및 70B 모델과 실제 다중 턴 대화 데이터셋을 사용해 평가한 저자 자체 보고이다[ITME p.9]. |

유리한 점: MLA는 기존 MHA 대비 KV cache 크기를 크게 줄여 추론 효율을 높이며, 장문맥 멀티턴 에이전트 서비스에서 중요한 메모리 및 대역폭 병목 문제에 대응할 수 있다[MLA p.6][MLA p.7]. ITME는 대용량 모델 가중치와 장문맥 KV 캐시를 원격 확장 계층에 오프로드하여 TB 규모 LLM 워크로드에 적합한 메모리 계층화를 제공한다[ITME p.2]. PCIe Gen5 인터페이스를 채택해 KV 캐시 교체에 필요한 높은 대역폭을 지원하며, 하드웨어/소프트웨어 선행 로딩으로 저장소 및 네트워크 지연을 효과적으로 숨긴다[ITME p.11]. Llama-3.1 8B 및 70B 모델과 실제 다중 턴 대화 데이터셋을 사용해 평가한 점에서 도메인 적용에 대한 실증적 근거가 있다[ITME p.9].

불리한 점: MLA는 정확도 손실 수치 및 측정 조건이 구체적으로 제시되지 않아, 도메인에서 허용 가능한 정확도 범위 내에 있는지 판단하기 어렵다[MLA p.6][MLA p.4]. 운영 복잡도 및 도입 후 인프라 변화에 관한 정보가 전혀 없어, 실제 서비스 적용 시 비용 변화를 평가할 수 없다[MLA p.4][MLA p.6]. 저자 자체 보고에 의존하고 있어, 도메인 특화 환경에서의 독립적 검증이나 실제 측정 수치인지 불명확하다[MLA p.6][MLA p.4]. 하드웨어 전제 조건에 대한 구체적 설명이 없어, 도메인에서 요구하는 하드웨어 환경과 완전히 부합하는지 알 수 없다[MLA p.6][MLA p.7]. ITME는 상용 CXL 하드웨어의 제한적 가용성과 PCIe Gen5 기반 하드웨어 요구로 인해 도메인 내 하드웨어 전제 조건을 충족시키기 어려울 수 있다[ITME p.11]. 활성화 및 작업 KV 캐시는 낮은 예측 가능성과 높은 지연 민감성으로 인해 GPU 또는 호스트 메모리에 배치해야 하므로, ITME가 오프로드하는 데이터 유형과는 다르다[ITME p.2]. 정확도 손실에 관한 구체적 수치나 측정 조건이 보고되지 않았다.

근거 없음: MLA의 정확도 손실 수치와 측정 조건, 운영 복잡도, 하드웨어 전제 조건, 제3자 검증 여부에 관한 근거가 없다. ITME의 정확도 손실 수치 및 측정 조건에 관한 근거가 없다.

## 5. 시사점

관점이 엇갈리는 지점은 진입 비용의 방향, 도메인 전환 시 제약, 실증 근거 해석에서 두드러진다. MLA는 소프트웨어 구조를 바꿔야 하므로 기존 모델을 그대로 쓸 수 없고, ITME는 하드웨어를 바꿔야 하므로 기존 인프라에 새 메모리 계층을 들여야 한다. 시장성 관점에서는 MLA의 생태계 채택, 도입 비용, 표준화 등 외부 확산과 지원의 불확실성을 문제 삼고, 도메인 적용 관점에서는 실제 적용 시 운영 복잡도, 인프라 변화, 검증 부족 등 내재적 리스크를 문제 삼는다. ITME는 시장성 관점에서 소프트웨어 호환성과 기존 환경 보완을 장점으로 보지만, 도메인 관점에서는 실제 하드웨어 전제 조건(PCIe Gen5, CXL 하드웨어)의 가용성 제약이 통합 가능성을 제한한다. 실증 근거 해석도 다르다. 시장성은 외부 독립 검증과 생태계 확산을 실증의 기준으로 삼고, 도메인은 저자 자체 실험이라도 실제 워크로드와 데이터셋을 사용한 평가를 실증으로 본다.

도메인을 바꾸면 두 기술의 제약도 달라진다. MLA의 KV cache 감소 효과는 온디바이스 환경에서 메모리 및 대역폭 제약을 완화하는 데 유리하게 작용할 수 있으나, 하드웨어 요구 조건, 전력 효율, 실제 모바일/엣지 환경에서의 성능 및 정확도 변화에 대한 근거가 없어 적용 가능성 및 효과를 판단하기 어렵다. ITME는 PCIe Gen5 기반 CXL-하이브리드 메모리와 NVMe SSD 등 서버급 하드웨어를 전제로 하므로, 스마트폰 및 엣지 디바이스의 전력, 공간, 비용 제약 환경에는 적용이 불가능하다. 클라우드 대규모 동시 서빙 도메인에서는 MLA의 KV cache 감소가 서버당 세션 수 증가 및 비용 절감에 기여할 수 있으나, 실제 클라우드 서빙 스택 내 구현, 확장성, 운영 복잡도 변화에 대한 근거가 없다. ITME의 TB급 메모리 확장 및 대역폭 증가는 대규모 동시 세션 처리에 유리하게 작용할 수 있으나, 실제 클라우드 환경에서의 비용 구조, 하드웨어 도입 및 운영 복잡도, 상용화 사례에 대한 근거가 없다.

이처럼 두 기술은 같은 도메인 전환에서 서로 다른 제약에 막힌다. MLA는 하드웨어 제약과 실제 모바일 환경에서의 성능 근거가 없고, ITME는 서버급 하드웨어 전제를 벗어날 수 없다. 평가 기준이 시장 확산/지지와 실제 적용/운영 리스크, 소프트웨어적 통합과 하드웨어적 실현 가능성, 외부 검증과 실제 워크로드 실험 등으로 나뉘어 관점에 따라 해석이 달라진다.

## 6. 한계점

이 평가는 1인 과제 범위로 한정했다. 네 관점 중 기술 성숙도(TRL) 관점과 이해관계자 관점은 범위에서 뺐다. 빠뜨린 것이 아니라 뺀 것이다. 두 기술의 공개 시점이 2024년 6월과 2026년 6월로 2년 차이 난다. 채택 현황을 나란히 놓으면 늦게 나온 쪽이 불리하게 읽힌다. 이 시간 차이를 감안하고 읽어야 한다.

시장 근거는 공개 자료만 썼다. 반도체 업계는 수율과 원가를 공개하지 않으므로 실제 채택 규모는 공개 정보로 확인할 수 없다. 웹 근거에 출처 등급을 붙였다. 일차는 논문과 코드 저장소와 벤더 공식 문서, 시장조사는 상업 조사기관 요약, 이차는 그 밖의 기사와 블로그다. 시장 규모 수치는 대부분 시장조사 등급이며 원본 보고서를 열어 대조하지 못했다. 같은 범주를 두고도 조사기관마다 수치가 크게 다른 경우가 있으므로 단일 수치를 그대로 믿으면 안 된다.

수집된 웹 근거의 등급 분포는 MLA: 일차 0건, 이차 0건, 시장조사 0건. ITME: 일차 0건, 이차 0건, 시장조사 0건이다. 웹 근거가 개별 기술이 아니라 범주 수준이었던 항목이 있다. 확증편향 감사에서 한쪽으로 기운 항목은 나오지 않았다. 취한 조치는 다음과 같다. 대칭_질의: 두 기술에 같은 질문 템플릿을 쓴다. 기술 이름만 바꾼다. 찬반_대칭: 관점마다 유리한 근거와 불리한 근거를 각각 따로 검색한다. 한쪽만 모이면 감사 단계에서 재수집한다. 순서_효과: 기술 제시 순서를 바꿔 두 번 실행하고, 결론이 달라지는지 기록한다. 근거_강제: 모든 평가 문장은 근거 원장의 id를 달아야 한다. 못 다는 문장은 버린다. 수치_대조: 보고서에 등장하는 숫자가 근거 원문에 있는지 코드로 대조한다. LLM 채점기만으로는 놓친다. 우열_금지: 한쪽을 높이거나 권하는 표현을 금지어 목록으로 두고 검사한다.

이 조치들은 관점별 대칭성과 근거 정확성을 높이기 위한 것이지만, 실제 산업 현장이나 비공개 생태계 채택, 내부 도입 비용, 장기적 운영 리스크 등은 반영하지 못한다. 웹 근거가 범주 수준에 머무른 항목은 개별 기술의 실제 시장성이나 도메인 적용 가능성을 직접 뒷받침하지 않는다.
